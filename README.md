# HJ212 模拟器

依据生态环境部《污染物自动监测监控系统数据传输技术要求》开发的桌面端协议模拟与调试工具，支持 **HJ/T 212-2005**、**HJ 212-2017**、**HJ 212-2025** 三个版本，支持 **TCP** 与 **串口（RS232/RS485）** 两种通道，界面支持 **跟随系统 / 亮色 / 暗色** 三档主题。

既可当**现场机（数采仪）**连到监控平台，也可当**上位机（平台侧）**接收多台现场机数据，用于联调、验收、回归测试和协议学习。

## 一、功能特性

### 协议能力
| 能力 | 说明 |
| --- | --- |
| 三版本兼容 | HJ/T 212-2005（版本位 0）、HJ 212-2017（版本位 1）、HJ 212-2025（版本位 2），Flag 标志位按 `(版本号<<2) \| (D<<1) \| A` 编解码 |
| 标准包结构 | `##` + 数据段长度(4) + 数据段 + CRC16(4HEX) + `<CR><LF>`，CRC 采用标准附录算法（CRC-16/MODBUS，多项式 0xA001，初值 0xFFFF） |
| 字段自动适配 | 按版本自动适配 PW 长度（6/9）、MN 长度（14/24）、PNUM/PNO、RF 补传标志等字段约束 |
| 长报文拆包 | 数据区超过 950 字节自动拆分为多包（PNUM/PNO），接收端自动重组展示 |
| 国密 SM4 | 按 HJ 212-2025 网络安全要求实现 **SM4 / ECB / 128bit / NoPadding** 加解密（纯 Python 实现，零额外依赖，已通过 GB/T 32907-2016 标准向量校验） |
| 自动应答 | 收到请求命令自动回 `9011`（请求应答）/ `9014`（数据应答）/ `9013`（执行结果），并按协议应答 `1011` 校时、`1061` 实时数据间隔 |
| 自动上报 | 按周期自动上报实时/分钟/小时/日数据，数值带随机波动与趋势，超限自动上报 `2051` 报警 |

### 通讯能力
- **TCP 客户端**：作为现场机主动连接监控平台
- **TCP 服务端**：作为上位机监听端口，支持多现场机并发接入并显示客户端列表
- **串口**：RS232/RS485 直连数采仪或仪表，波特率/数据位/校验位/停止位可配
- 编码可切换 UTF-8 / GBK / GB2312 / Latin1（默认 UTF-8，符合标准对汉字的要求）
- 字节流粘包、断包自动处理

### 界面能力
- 左侧导航 + 多页面工作区：**连接管理 / 报文构建 / 数据模拟 / 报文监控 / 通信日志 / 编码字典 / 系统设置**
- 报文构建：字段表单 + 数据区键值表格 + 实时预览（含 CRC、Flag、包数）+ 一键发送
- 报文解析：粘贴报文即解析为字段树，展示版本号、拆包、应答、CRC 校验结果
- 报文监控：收发列表（方向着色）+ 字段级解析树 + 原文/十六进制对照
- 通信日志：分级着色（接收/发送/警告/错误），支持过滤与导出
- 编码字典：内置命令编码 CN、系统编码 ST、结果编码、监测因子库，支持关键字过滤
- 主题：跟随系统 / 亮色 / 暗色一键切换，配置自动持久化

## 二、快速开始

### 方式 A：直接下载编译好的程序（推荐）

1. 打开本仓库 GitHub 页面右侧 **Releases**，下载对应系统的压缩包
   - `HJ212Simulator-Windows-x64.zip`
   - `HJ212Simulator-macOS-universal.zip`
   - `HJ212Simulator-Linux-x64.zip`
2. 解压后双击 `HJ212Simulator`（Windows 为 `HJ212Simulator.exe`）即可运行，无需安装 Python。

> 若 Actions 正在构建，可在仓库 **Actions** 页进入最新一次工作流，在页面底部 **Artifacts** 区域直接下载。

### 方式 B：源码运行

```bash
git clone https://github.com/<你的用户名>/HJ212-Simulator.git
cd HJ212-Simulator
pip install -r requirements.txt
python src/main.py
```

### 方式 C：本地打包

```bash
pip install -r requirements.txt
python build.py          # 自动跑测试 + 打包，产物位于 dist/
```

## 三、典型用法

### 1. 模拟现场机上报数据（连平台）
1. 「连接管理」→ 选择 **TCP 客户端** → 填写平台 IP 与端口 → **打开通道**
2. 「系统设置」→ 选择协议版本、填写 MN（24 位）与 PW
3. 「数据模拟」→ 勾选监测因子 → 选数据粒度（如 2011 实时数据）→ 设置周期 → **启动自动上报**
4. 「报文监控」查看收发详情，「通信日志」查看交互过程

### 2. 模拟平台接收数据（等现场机连入）
1. 「连接管理」→ 选择 **TCP 服务端** → 设置监听端口 → **打开通道**
2. 现场机（或另一台本软件）连接到该端口
3. 勾选「自动应答」，本软件会自动回复 `9011/9014/9013` 等应答包
4. 客户端列表实时显示已接入设备

### 3. 串口调试
选择 **串口** → 选择串口号、波特率（常见 9600）→ 打开通道 → 其余操作与 TCP 一致。

### 4. 手工构造报文
「报文构建」填写 QN/ST/CN/PW/MN，在数据区表格中填写 `字段名/值`（如 `DataTime`、`a21026-Rtd`），
点「生成报文」即可看到完整通讯包：

```
##0142QN=20260922081637238;ST=32;CN=2011;PW=123456;MN=010000A8900016F000169DC0;Flag=5;CP=&&DataTime=20260922081636;a21026-Rtd=12.345;a21026-Flag=N&&1E0C
```

### 5. 验证 SM4 加密（2025 版）
「系统设置」→ 勾选 **启用 SM4 加密** → 填写 32 位 HEX 密钥（16 字节）→ 收发明文自动加/解密，
日志中会提示解密后的明文。

## 四、协议实现说明

- **通讯包**：`##` + 数据段长度(4) + 数据段 + CRC16(4HEX) + `<CR><LF>`；CRC 为数据段 ASCII 的 CRC16 校验，校验失败按超时重发处理。
- **数据段**：`QN=...;ST=...;CN=...;PW=...;MN=...;Flag=...;[PNUM/PNO/RF]...;CP=&&数据区&&`
- **数据区**：字段与值用 `=` 连接，同一项目不同分类值用 `,` 分隔，不同项目用 `;` 分隔。
- **Flag 标志位**：`V5~V0` 版本号（000000=2005，000001=2017，000010=2025）、`A` 是否应答、`D` 是否拆分包。
- **HJ 212-2025 相对 2017 的主要变化**（工具已覆盖）：统一设备标识与联网注册流程、新增用电/用能/工况/视频/碳排放等传输编码、设备运行参数与工作状态穿透上传、登录与参数修改日志上传、互联网传输采用国密 SM4 加密与密钥管理。
- 编码表（CN/ST/因子）依据标准正文及附录整理，存放于 `src/core/commands.py`，可直接修改以适配地方平台扩展要求。

## 七、常见问题

**Q：Windows 提示"Windows 已保护你的电脑"？**
A：程序未做代码签名，属正常提示，选择"仍要运行"即可。

**Q：Linux 启动报缺少 `libxcb-cursor0` 等？**
A：执行 `sudo apt install libxcb-cursor0 libxkbcommon-x11-0 libegl1` 安装 Qt 运行库。

**Q：串口列表为空？**
A：确认已安装 `pyserial`（`pip install pyserial`），并确认当前用户有串口访问权限（Linux 需加入 `dialout` 组）。

**Q：平台收不到我上报的数据？**
A：依次检查：协议版本是否与平台一致（影响 Flag 与 MN/PW 长度）、MN 与 PW 是否登记、
字符编码（部分老平台用 GBK）、平台端口与防火墙。
